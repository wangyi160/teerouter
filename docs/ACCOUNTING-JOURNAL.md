# 本地流水日志

`--journal-dir PATH` 启用可选的流水持久化，目录必须由运行环境提供持久化磁盘。未指定时维持内存模式。生产启用要求 `dstack-tdx` 构建以及本地受测量 guest 的 `/var/run/dstack.sock`；无密钥、错误密钥或损坏日志会拒绝启动，不静默创建替代账本。现有内存流水不能在事后恢复。

## 提交与上传

- 请求结束、错误或取消形成计费记录后，同步提交 SQLite WAL（`synchronous=FULL`）。只新增、修改或删除变化的行，不按每个请求重写整个数据库。
- 日志保存流水、累计用量、上次同步余额、未结算批次消费、上传游标和冻结批次。不保存用户输入、模型回答、上游账号凭证或 TLS 私钥。公开模式拒答只保存类型。
- 普通上传按 `interval_seconds` 调度，默认 300 秒。失败结束本轮，下一周期再处理未确认数据，没有 30 秒重试分支。空闲周期也保持调度间隔。
- 单个批次仍受 512 条和约 900 KB 限制，同一周期依次上传已有积压；任何一批失败立即结束本轮。新到达数据不会无限延长本轮。
- 发出网络请求前，冻结批次、随机数、签名与调度时间必须先持久化。确认丢失或进程重启后继续发送完全相同的批次，云端按编号和摘要去重。
- 只有校验通过的云端持久化 ACK 才会清理对应流水和冻结批次。清理与推进上传游标是同一个本地事务，不等待管理平台结算。SQLite 释放的页面可供后续记录复用，文件大小不必立即缩小。
- 已上传但未结算的消费汇总继续保存。管理平台原有结算 ACK 原子更新同步余额并清除已结算消费，重复 ACK 不重复扣费。

## 重启恢复

新进程使用新的 `boot_id` 和签名密钥，业务仍等待管理平台初始化。管理平台在初始化前注册新的 TEE 签名身份，再下发业务配置。Router 核验本地日志的应用身份、序号及管理端已确认的批次边界，恢复流水与其对应的旧余额/消费组合；管理端新余额通过已有结算接口应用。

如果云端已保存、管理端已结算，但 Router 尚未收到上传 ACK，恢复时仍保留原批次，下一周期获取云端重复上传确认后再接受该边界的结算。期间按本地旧余额减去消费进行准入，不把新余额与旧消费重复相减。

日志只保护提交完成的记录，不补造崩溃前未完成的模型调用或官方 usage。持久化不等于外部备份；删除整个磁盘、硬件损毁及尚未对外确认的整盘回滚不承诺无损恢复。

## 加密与限额

AES-256-GCM 密钥来自本地 dstack 的 `teerouter/accounting-journal/v1` 派生路径。每行使用独立随机 nonce，行名作为认证上下文，另有加密摘要覆盖完整行集合，防止单独删除、替换或移动记录。没有接受外部日志密钥的 CLI 选项。

数据库使用独占连接，拒绝第二个进程同时写同一目录。逻辑日志上限 64 MiB，数据库上限 256 MiB，WAL 定期 checkpoint；原有内存队列和未结算批次限额仍有效。达到任一上限或发生写盘错误会关闭新模型请求准入，保留已提交数据；写盘错误不会退回内存模式，需恢复磁盘并重启后检查。

`/admin/status.accounting_journal` 和 `/admin/metrics.storage.journal` 显示是否启用及写盘健康状态。该机制不改变充值、提现和管理平台最终账务的所有权。
