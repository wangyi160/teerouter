# 本地流水日志

**简体中文** | [English](ACCOUNTING-JOURNAL.en.md)

Router 的可选账务日志保存已提交的消费与投递状态，使用 SQLite WAL 和认证加密。未启用时相关状态只在内存中。日志初始化要求可用的本地 dstack 密钥派生接口；密钥不可用、认证失败或日志损坏时拒绝初始化，不静默创建替代账本。

<a id="commit-and-upload"></a>

## 提交与上传

- 请求结束、失败或取消形成计费事件后，以 `synchronous=FULL` 事务提交变化行，不为每个请求重写整个数据库。
- 保存流水、累计用量、同步余额、未结算消费、上传游标和冻结批次。不保存请求正文、回答、上游凭证或 TLS 私钥；公开模式拒答只含类型。
- `interval_seconds` 默认 300。失败结束本轮，下一周期重试；空闲周期也维持调度间隔。
- 单批最多 512 条并受约 900 KB 大小限制。同一周期处理已有积压，任意一批失败即结束；新事件不会无限延长本轮。
- 发起网络请求前，冻结批次、随机数、签名与调度时间先持久化。确认丢失或进程重启后，重发完全相同的签名字节。
- 通过校验的持久化上传 ACK 在同一事务中释放对应明细、清除冻结批次并推进上传游标，不清除消费。
- 结算 ACK 单独更新同步余额并清除确认边界内消费；重复确认不会重复应用，边界之后的请求保留。

<a id="recovery"></a>

## 恢复

新进程具有新的 `boot_id` 和签名密钥，在业务初始化时校验日志的应用身份、序号及确认边界。历史流水按日志中对应的余额/消费组合恢复，后续新余额通过结算入口应用。

远端已保存但本地尚无上传 ACK 时，原批次仍保留。重复上传取得合法 ACK 后，Router 才能接受该边界的结算。期间使用本地旧余额减去消费，不将新余额与旧消费重复相减。

日志只保护成功提交的记录，不能补造崩溃前未完成的调用或未观察到的官方用量。未生成、未提交及写入失败的在途尾部不受恢复保证保护；整个日志副本回滚、删除或介质损毁也不能保证无损恢复。

<a id="encryption-capacity-and-status"></a>

## 加密、容量与状态

AES-256-GCM 密钥来自本地 dstack 的 `teerouter/accounting-journal/v1` 派生路径。每行使用独立随机 nonce，行名作为认证上下文；另有加密摘要认证完整行集合，防止单行删除、替换或移动。日志不接受外部提供的密钥。

独占数据库连接拒绝第二个进程同时写入。逻辑日志上限 64 MiB，数据库上限 256 MiB，WAL 定期 checkpoint；内存队列与未结算批次限额同时生效。达到上限或写入失败会关闭新模型请求准入，保留已经提交的数据，不回退到内存记账。

`/admin/status.accounting_journal` 和 `/admin/metrics.storage.journal` 报告启用状态与写入健康。源码见 `src/vault/journal.rs`；提交、确认和恢复的回归测试位于 `src/vault/journal/tests.rs`。
